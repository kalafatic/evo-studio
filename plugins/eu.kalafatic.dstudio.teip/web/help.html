EVO-Studio Overview

EVO-Studio (EVO Studio) is the professional IDE and headless Harness Platform of the EVO product family. One shared core runs two faces: the desktop IDE (projects, source editing, harness execution, monitoring and review) and the headless server that exposes the same core through the TEIP 1.1 provider endpoints (/teip/v1/*) plus this web interface and API.

The web interface served here talks to the same backend the desktop application uses: projects, coding tasks, inference engines, agent profiles and live events are shared. Anything you do in the browser is immediately visible in the IDE and vice versa.

This help site documents the running instance: the menu structure, keyboard shortcuts, context help anchors, the headless CLI commands and the diagnostics surface.

Getting Started

  1. Open a project. In the desktop IDE use Project → Open Project…; in the web interface use the Open Project… button in the toolbar and enter the path of a folder or repository.
  2. Configure the coding harness. Open the Harnesses view (menu Harness → Show Harness View) to select the default harness (EVO-Code is the family default; OpenCode, Aider and Claude Code adapters are available).
  3. Run a coding task. Press Ctrl+Enter (⌘+Enter on macOS), use Run → Run Coding Task…, or the Coding Task panel in the web interface. The execution appears in the Executions view and its log output in the EVO-Studio Execution Console.
  4. Review the changes. After an execution, open the Change Review view to accept or reject each changed file.
  5. Use the AI assistant. The Inference Engines view manages engines (ENR is the family default) and models; the web interface offers a chat assistant with streaming responses and reusable sessions.
  6. Headless mode. Run the product with -headless (or the server application): it serves the TEIP/API surface on port 48080 by default and offers an interactive CLI when a terminal is attached (see CLI Commands).

Configuration is stored in ~/.dstudio/dstudio.properties and business state in ~/.dstudio/dstudio.db; the Eclipse workspace holds only the workbench layout.

Keyboard Shortcuts and Menu Structure

Web interface shortcuts

  • Enter — send the prompt; Shift+Enter — newline.
  • Ctrl+K / ⌘+K — focus the prompt input.
  • Ctrl+N / ⌘+N — start a new conversation.
  • Esc — cancel the running inference.

Global shortcuts

  • Ctrl+Enter / M1+Enter — run the harness on the active project (opens the Run dialog).
  • F5 — refresh the project list.
  • F1 — context help: opens this help site at the section describing the currently active view (see Context Help).

Tools menu

  • Tools → Open Terminal — opens a system terminal in the active project directory (falls back to your home directory). Supported emulators: x-terminal-emulator, gnome-terminal, konsole, xterm. The same action is available in the Project Explorer context menu (on projects and on folder entries).
  • Tools → Open Web Interface — opens this web interface in your browser on the port the backend server is actually bound to.

Help menu

  • Help → Help Contents — this page (#top).
  • Help → Getting Started — #getting-started.
  • Help → Context Help — help for the active view (same as F1).
  • Help → Keyboard Shortcuts — #shortcuts.
  • Help → CLI Commands — #cli.
  • Help → Diagnostics — opens /api/diagnostics in the browser.

Context Help

Pressing F1 (or Help → Context Help) opens this page at the section for the active view. Views without a dedicated section fall back to this one.

Project Explorer

The Project Explorer lists the registered projects and their files. Double-click a file to open it in an editor. The context menu offers: Open (files), Copy Path (clipboard), Open Terminal (folders and projects — a terminal in that directory), the unified contextual actions for projects (create session, close project, …), Open Web Interface and Refresh. Empty space shows Open Project….

Harnesses

The Harnesses view manages the coding-harness adapters registered with EVO-Studio (EVO-Code, OpenCode, Aider, Claude Code). You can select the default harness, enable or disable harnesses, run a live connection test and edit each harness configuration (model, provider type, auto-approve, …). Harness configuration is persisted in the database and shared with the headless server.

Executions

The Executions view lists every coding execution (task) with its status, harness, provider, agent, model, project and progress. Buttons run a new task, cancel the selected one and refresh the list; double-clicking an execution shows its details and event history. Open executions are reconciled to FAILED on restart (they cannot be resumed).

Inference Engines

The Inference Engines view manages the inference-engine adapters (ENR is the family default; Ollama, OpenAI-compatible and Anthropic are alternatives). Per engine you can select the default, enable/disable, test the connection, discover and load/unload models, and inspect the engine runtime status (CPU/memory/GPU). The web interface uses the same registry for the AI assistant.

Agent Profiles

The Agent Profiles view manages reusable agent personas: system instructions, role, tool permissions, restrictions and the preferred harness/provider/model. Profiles are data, not adapters — create, edit, clone, import/export and delete them here; the compatibility check validates a profile against a concrete execution environment. Profiles are shared with the headless server and the TEIP surface.

Change Review

The Change Review view inspects the working-tree changes produced by an execution: select an execution, review each changed file with the compare editor, then accept or reject the changes. Decisions are persisted and visible to the execution history.

CLI Commands (headless)

When EVO-Studio runs headless (-headless or the server application) with a terminal attached — or with commands piped to stdin — it offers a small command line. A leading / is optional, commands are case-insensitive, and exit/stop (or end-of-input) shut the server down gracefully. The daemon flag (-Ddstudio.daemon=true or --daemon) keeps the server blocking on its latch regardless of stdin.

help [topic]                       Show the command list or detailed topic help.
status                             Lifecycle stage, server address/port, web URL.
web                                Print the web interface URL.
terminal                           Print the workspace directory; open a terminal if possible.
models list | models show <id>     List engines and their models, or show one model.
sessions list | sessions show <id> | sessions cancel <id>
                                   List, inspect or cancel harness executions.
providers list | providers test <id>
                                   List harness providers or test one connection.
agents list                        List agent profiles.
config show                        Show non-secret configuration values.
logs show                          Show the most recent event-stream entries.
start                              Ensure the server is running (starts automatically).
restart                            Restart the TEIP/API server on its configured port.
stop                               Stop EVO-Studio gracefully.
exit                               Exit the CLI (shuts EVO-Studio down like 'stop').
  • status/web resolve the port from the actually bound server — the port is never hardcoded.
  • sessions maps to the execution service: list, show and idempotent cancel only (no delete/create).
  • providers maps to the harness registry: EVO-Studio's harness adapters are the family's coding providers.
  • config show never prints secrets (auth tokens are excluded).
  • logs show tails the buffered event stream — the same stream served live over SSE at /api/events.
  • Unknown commands suggest the nearest matches: Unknown command 'x'. Did you mean: …?

Diagnostics

/api/diagnostics (JSON) reports the running instance: the harness registry (id, type, enablement, connection status and supported provider types) and the active executions. /api/events is the live SSE event stream carrying session/task/inference events with monotonically increasing sequence numbers; clients replay missed events with ?afterSequence=…. Both endpoints require the bearer token unless dev mode is enabled (dstudio.teip.devMode=true). /api/status reports application, version and readiness.

EVO-Studio diagnostics port 48180 is reserved by the family convention (family +10000); this build serves diagnostics on the primary TEIP port as documented above.
